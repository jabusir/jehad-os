# ADR-0004 — Memory promotion pipeline with assertion-kind truth semantics

- **Status:** accepted
- **Date:** 2026-09-16

## Context

The directive defines four memory classes (§3.5) and states that nothing
becomes canonical automatically — promotion is a gated pipeline (§3.5 "Memory
promotion"). The external review required tightening the truth semantics: a
direct user statement can canonically establish a preference, intent,
commitment, personal decision, or self-declared plan, but a user statement about
the external world must remain a claim until independently verified ("Jehad
said X" is not "X is true") — review §8. False semantic canonization is threat
T14 (review §24). Work-domain content must be blocked from the personal
semantic store (T3; §4.4), and federated/opaque domains contribute only
policy-sanitized metadata (or nothing) — cleanup §3. The marker (plan §6.2):

> Promotion rules are data (config), not model judgment. First
> correction-scope taxonomy (§29) ships as an enum on the candidate.
> **[ADR-0004]** (extended: assertion-kind/truth semantics).

## Decision

1. All semantic memory enters through the promotion pipeline (plan §6.2): a
   harness/model proposes a `MemoryCandidate`; a classifier assigns a class
   (discard | working | episodic | semantic | preference; commitment | decision
   | assumption | procedural | policy) and an `assertion_kind`
   (observed | user_declared | externally_sourced | model_inferred | computed).
2. The gate applies, in order: (1) provenance attached (source event/run,
   model, prompt version); (2) domain check — work content blocked from the
   personal semantic store, abstract method-level learning allowed, federated
   domains contribute policy-sanitized metadata only, opaque domains contribute
   no semantic payload by default (cleanup §3); (3) sensitivity/retention
   classification plus model-egress check (ADR-0012); (4) confidence and
   conflict check — contradicting facts are both kept with the conflict
   recorded, escalating to review if material; (5) write to the matching store.
3. Truth semantics: semantic writes are proposals landing in the review queue
   unless (a) `assertion_kind=user_declared` AND the class is one a person can
   canonically establish by stating it (preference, intent, commitment,
   personal decision, self-declared plan), or (b) the class is episodic. A
   user-declared claim about the external world ("Company X has 3M customers")
   is stored as a user-supplied claim, evidence-linkable via the `evidence`
   primitive (plan §7, review §20), and is never auto-promoted to verified
   semantic fact.
4. Promotion rules are data (configuration), not model judgment; the §29
   correction-scope taxonomy ships as an enum on the candidate.
5. Eval gates (plan §13): promotion classification at ≥0.9 bootstrap accuracy
   across the seven classes, including the claim-vs-fact distinction; the
   claim-not-fact acceptance test is part of M5.

## Consequences

- The kernel cannot silently canonize hearsay, inferences, or third-party
  claims; T14 is structurally mitigated, not prompt-mitigated.
- Review queue carries semantic proposals (batched, per the attention
  guardrail), which is accepted human overhead for trustworthy canon.
- Work-domain content has a hard gate (T3); employer specifics never enter
  personal semantic memory.
- We explicitly decline: auto-canonization of anything, LLM-judged promotion
  rules, an embedding/retrieval-based episodic store (pgvector is on the
  not-now list, plan §16), and any "the model said so" provenance.
- The pipeline ships at M5 with the extraction workflow; assertion_kind and
  gate_result are columns on `memory_candidates` (plan §7).
