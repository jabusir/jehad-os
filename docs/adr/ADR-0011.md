# ADR-0011 — External action intent/attempt/outcome semantics (unknown state, reconciliation)

- **Status:** accepted
- **Date:** 2026-09-16

## Context

The directive requires an audit trail that can reconstruct what actually
happened, not what was intended (§26.4), and human approval gates for
high-risk actions (§26.3). The external review found "audit written before
effect" insufficient for external side effects: after a lost network response
the audit log cannot honestly say sent or not-sent without provider
confirmation — this affects emails, calendar changes, purchases, external
APIs, transfers, production operations, and matters especially because Finance
eventually enters this control plane (review §6). The final-cleanup review
required explicit state ownership so implementation does not create two
competing state machines (cleanup §5). External action ambiguity is threat
T13 (review §24). The marker (plan §9):

> **[ADR-0007]** (extended), **[ADR-0009..0012]**.

## Decision

1. Every external side effect is modeled as `action_intents` →
   `action_attempts` (plan §7, §9).
2. Each state has exactly one canonical owner (cleanup §5):
   - `ActionIntent.status` owns the intent-side states:
     proposed → approved → prepared | cancelled;
   - `ActionAttempt.outcome` owns the execution-side states:
     executing → succeeded | failed | **unknown** → reconciled.
   Combined lifecycle: intent proposed → approved → prepared → attempt
   executing → attempt outcome (+ reconciled).
3. One intent may have many attempts: retries and reconciliation append new
   attempts; the history of an earlier ambiguous attempt is never
   overwritten.
4. `unknown` is a first-class outcome (e.g. after a response timeout) until a
   reconciliation workflow resolves it via provider refs. Provider idempotency
   keys are used where available and stored on the attempt.
5. Audit references these records; a pre-effect audit entry records intent,
   never completion. After a lost response the honest state is `unknown`.
6. Designed now because Finance eventually enters this control plane; Phase 1
   exercises the full semantics with a fake provider adapter — no real
   external actions until E3/E4 (plan §9).

## Consequences

- The system never overclaims: audit cannot assert success it did not observe
  (T13); M4 acceptance — action attempt timeout → outcome `unknown`, audit
  never claims success.
- Money movement and contracts remain prohibited (autonomy ceiling,
  ADR-0007), but their control-plane semantics exist before Finance arrives,
  avoiding a rewrite under load.
- Slightly more write ceremony per external effect (intent row, attempt rows,
  reconciliation path) — accepted as the cost of honest state.
- We explicitly decline: treating a pre-effect audit entry as completion
  proof, overwriting ambiguous attempt history on retry, blanket
  "probably succeeded" heuristics, and real provider integration in Phase 1.
