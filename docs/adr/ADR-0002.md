# ADR-0002 — TypeScript strict; no harness/vendor SDK imports in packages/core

- **Status:** accepted
- **Date:** 2026-09-16

## Context

The directive requires models, harnesses, and workflow products to be
replaceable components, never product identity: "Do not let implementation
convenience collapse the architectural boundaries" (§33; §3.2). Durable workflow
usage must stay behind `WorkflowRuntime` with no provider-specific primitives
scattered through domain code (§11.9). The external review approved excluding
harness/provider SDKs from `packages/core` (review §1). AGENTS.md states the
rule as a hard convention: domain code imports interfaces only from
`packages/adapters`. The plan's marker (plan §4.2):

> **[ADR-0002]** TypeScript strict; no harness/vendor SDK imports in `packages/core`.

## Decision

1. All kernel code is TypeScript with `strict` enabled (toolchain per §33
   defaults as adopted at M0: Node 22, pnpm).
2. `packages/core` — domain model, policy, memory, events — is pure TypeScript
   with zero imports of harness SDKs (OpenClaw, Hermes, Claude Code, Codex),
   model-provider SDKs, or the workflow vendor's SDK (Inngest).
3. Vendor and harness touchpoints live only in `packages/adapters` (port
   interfaces plus implementations) and `packages/workflow/inngest` (the
   WorkflowRuntime implementation). The `WorkflowRuntime` port interface itself
   lives in `packages/adapters` with the other ports (plan §4.2).
4. The M3 acceptance criterion enforces this mechanically: no Inngest imports
   outside `packages/workflow` (plan §15, M3).

## Consequences

- `packages/core` stays compilable and testable without any vendor account,
  credential, or network dependency; vendor swap costs are confined to adapter
  packages.
- Port interfaces are defined in Phase 1; concrete adapters land only when
  needed (IntegrationAdapter at E3, HarnessAdapter at Phase 3 — cleanup §1).
- Slightly more interface plumbing than direct SDK calls; accepted as the price
  of replaceability (§3.2).
- We explicitly decline: SDK convenience imports "just this once" in core,
  vendor types leaking into domain signatures, and any Mac-specific behavior in
  `packages/core` (E2 disposition, plan §19).
- Code review treats a vendor import inside `packages/core` as a blocking
  defect (AGENTS.md hard rule).
