# ADR-0001 — Monorepo, single service, Postgres-only persistence

- **Status:** accepted
- **Date:** 2026-09-16

## Context

Jehad OS is a greenfield control plane: the kernel owns world state, policy, events,
memory promotion, audit, and the review queue (AGENTS.md; §3.1). The directive's
technical defaults point at TypeScript + PostgreSQL with migrations under source
control (§33), and the product guardrails demand boring, durable, reversible
infrastructure — no microservices, no k8s, no queue broker sprawl (plan §3; §42).
The external review explicitly approved the "single TypeScript monorepo" and
"boring modular monolith before microservices" as architectural choices
(review §1). The only state that does not belong to the kernel is workflow
*execution* state, which the revised workflow-runtime decision assigns to Inngest
behind the `WorkflowRuntime` interface (plan §12, ADR-0008).

The plan's marker (plan §4.2):

> **[ADR-0001]** Monorepo, single service, Postgres-only persistence (Inngest owns
> workflow-execution state only, not world state — plan §12).

## Decision

1. Build a single TypeScript monorepo (pnpm workspaces, Node 22 LTS) holding the
   entire control plane, laid out per plan §4.2 (`apps/api`, `apps/worker`,
   `packages/core|adapters|workflow|db`, `procedures/`, `docs/`, `infra/`,
   gitignored `data/`).
2. Deploy one API service (Fastify) and one workflow-serving app
   (`apps/worker` — registers/serves workflow functions per the selected
   Inngest deployment model; NOT a fixed always-on daemon assumption, the M3
   spike determines the concrete shape — cleanup §6); verticals arrive as
   modules inside the same kernel, not as separate services (plan §4.1).
3. PostgreSQL 16 is the only persistence layer we operate for canonical state —
   world model, events, outbox, audit, grants, artifacts (Phase 1 default,
   plan §7) — with SQL migrations under source control (AGENTS.md).
4. Inngest owns workflow-execution/checkpoint state only, behind
   `WorkflowRuntime` (plan §12). Inngest is never a source of truth for world
   state; the canonical event ledger is not duplicated inside it.

## Consequences

- One repo, one deployable API, one workflow-serving app (shape per M3
  spike), one database to back up and restore
  (M1 backup/restore covers rows and artifact content — review §11, T16).
- Local dev needs no Docker and no queue broker beyond Postgres (plus the
  Inngest dev server per ADR-0008; AGENTS.md "no Docker required").
- Adding a vertical means adding a module, not a service; the migration path to
  more processes exists but is not exercised (cleanup §9: do not reopen).
- We explicitly decline to build: microservices, k8s, Kafka or any additional
  message broker, a second canonical datastore, and any duplication of the
  event ledger inside the workflow runtime (plan §16).
- If a future phase genuinely needs a second datastore, that is a new ADR.
