# ADR-0006 — Event model: noun-first naming, idempotency, schema-version compatibility contract

- **Status:** accepted
- **Date:** 2026-09-16

## Context

The directive defines an event layer as the system's spine (§6) and uses
subject.verb naming. The plan inverted to noun-first (`commitment.detected`)
for grouping-friendliness — disagreement D4, blessed by the owner with the
added condition that a compatibility contract be established now (review §18,
review §21/D4): event names immutable once released, explicit payload
`schemaVersion`, consumers tolerate additive fields, breaking changes require a
new version or new type. Duplicate/replayed events are threat T5; idempotency
is therefore structural. The marker (plan §8):

> … breaking payload changes require a new schema version (or new event type)
> — enforced from the first event, before OpenClaw / remote work domains /
> multiple workers consume the stream. **[ADR-0006]**

## Decision

1. Adopt the plan §8 envelope, stored verbatim in `events` (plus `outbox` for
   dispatch): `id` (uuid-v7), `type`, `schemaVersion`, `source`
   (cli.capture | openclaw.channel | adapter:&lt;id&gt; | internal),
   `occurredAt`, `recordedAt`, `domainId`, `idempotencyKey`
   (sha256(source + external id)), `sensitivity`, `payload`, `runId`.
2. Event types are named `<noun>.<verb_past>` (noun-first; D4 blessed). Catalog
   v1 is the plan §8 list (`capture.recorded`, `commitment.detected`,
   `commitment.due`, `commitment.overdue`, `decision.recorded`,
   `assumption.changed`, `memory.proposed`, `memory.promoted`, `run.started`,
   `run.completed`, `run.failed`, `verification.failed`,
   `escalation.raised`, `escalation.resolved`, `grant.issued`,
   `grant.revoked`, `brief.generated`).
3. Idempotency and immutability rules: events are immutable once accepted;
   `idempotency_key` is unique via constraint; every source defines its
   external id — adapter retries reuse it, distinct real-world occurrences get
   a new one (the CLI mints a fresh uuid per `capture`/`decide` invocation, so
   identical words captured twice are two events, never a dedupe); handlers
   are idempotent (safe to replay); outbox dispatch is at-least-once.
4. Compatibility contract (review §18), enforced from the first event:
   event names are immutable once released; every payload declares
   `schemaVersion`; consumers tolerate additive fields; breaking payload
   changes require a new schema version or a new event type.
5. The SourceAdapter/event design stays sufficient for the future observation
   layer (Calendar, Email, Slack, Granola, iMessage, GitHub, Linear, financial
   accounts, voice, web, home events) — architecture now, wiring later; a
   connector is built only when the system knows what state it will derive
   from it (cleanup §8).

## Consequences

- Replays and adapter retries are safe (T5 mitigated structurally); M2
  acceptance: duplicate event → 200-noop; outbox replay is safe.
- The stream is consumable by OpenClaw, remote work domains, and multiple
  workers without renegotiation, because the contract predates them.
- Renaming or reshaping a released event is prohibited — only new versions or
  new types; this discipline is permanent.
- We explicitly decline: subject-first naming, unversioned payloads,
  best-effort "tolerant reader" reinterpretation of breaking changes, and
  ingest-for-ingest's-sake connectors.
- Event types consumed by workflows trigger dispatch through
  `WorkflowRuntime` (plan §12); no vendor event format leaks into the
  envelope (ADR-0002).
