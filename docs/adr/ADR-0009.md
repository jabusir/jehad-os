# ADR-0009 — Local authentication: Keychain bearer credential per principal, bootstrap migration at M0, loopback is not identity

- **Status:** accepted
- **Date:** 2026-09-16

## Context

The original plan (assumption A15) deferred transport authentication because
the API binds to 127.0.0.1 until a non-loopback caller exists. The owner's
external review rejected that: loopback binding is a network boundary, not an
identity boundary — a compromised browser, local process, agent, or package on
the same Mac must not automatically receive Jehad OS authority; add minimal
authentication immediately, in Phase 1 (review §4, which replaces A15). The
final-cleanup review resolved the resulting M0/M1 ordering problem with a
bootstrap migration so the API never exists unauthenticated (cleanup §2).
Unauthenticated local access is threat T11 (review §24). The marker (plan §9):

> **[ADR-0007]** (extended), **[ADR-0009..0012]**.

## Decision

1. The API requires an authenticated principal on every call from day one
   (M0). Chosen mechanism: a random local **bearer credential stored in macOS
   Keychain**. `josctl` and future harnesses each get their own credential —
   one credential per principal (review §4). Unix-domain socket + filesystem
   permissions was the alternative; bearer wins for the later OpenClaw path
   (E4).
2. M0 ships a minimal bootstrap migration `000_bootstrap_auth.sql`
   (principals only: id, type, name, credential_hash, created_at) so
   authentication never waits on the full M1 schema; M1 applies the remaining
   schema-v1 migrations (cleanup §2). Invariant: the API must never exist in
   an unauthenticated state merely because the full world-model schema has not
   yet landed. The credential secret itself lives in Keychain; only its hash
   is stored (plan §7; review §4/§5 secrets discipline, §26.5).
3. Loopback binding (127.0.0.1) is retained as defense-in-depth but is a
   network boundary, **not** an identity boundary.
4. Principal types: `user | harness | service | workflow` (review §4). A
   capability grant is issued to a principal/run, never assumed from network
   location (ADR-0007).
5. Harness identities and transport hardening arrive with the first
   non-loopback caller at E4; A15 is replaced accordingly (plan §17 A15).

## Consequences

- Unauthenticated requests are rejected from the first boot: M0 acceptance —
  unauthenticated API request → 401; M2 re-verifies at the event ingest API;
  review §25 test "unauthenticated localhost request → rejected" (M2).
- Every caller is attributable in the audit trail via its principal, which
  ADR-0007 grants and audit entries build on.
- Per-principal credentials mean a harness compromise does not leak the
  user's credential, and revocation is per principal.
- We explicitly decline: OAuth (explicitly not built — review §4), trusting
  loopback reachability as identity, a shared machine-wide token, and secrets
  in git/logs/events (AGENTS.md).
- macOS Keychain is a dev-machine convenience, not a kernel dependency:
  Mac-specific behavior stays out of `packages/core` (E2 disposition); the
  primitive is "local secret store + hash on the principal row."
