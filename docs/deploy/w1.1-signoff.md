   event + producer resolve/3-branch write in ONE transaction (Pool path:
   explicit BEGIN/COMMIT; client path: caller's txn). Delivery enqueue moved
   AFTER commit (`deliverOutcomeAttentionNow`), failure caught + audited
   (`attention.enqueue_failed`), recovered by `attention-liveness`.
   Regression: forced producer throw ⇒ `outcomes.status='accepted'` unchanged,
   0 `outcome.status_changed`, 0 attention rows.
2. **Snooze lifecycle** — `updated_at` = mutation time; expired snooze renders
   in Today needs-you immediately and the sweep formally wakes it
   (`attention.woken`); retry treats expired snoozes as delivery-eligible;
   a changed occurrence while snoozed wakes + delivers; unchanged stays
   snoozed + deferred. All four behaviors regression-tested.
3. **Outcome card controls** — producer stores the full W1 control set
   (Open outcome · Resolve · Snooze · Dismiss · Useful/Noise/Interruptive);
   bump/reopen refresh evidence_refs + actions. **Live-confirmed:** the 2Q3
   card over tailnet HTTPS rendered exactly
   `Open outcome / Resolve / Snooze 60m / Dismiss / Feedback: useful / noise / interruptive`.
4. **Kill switch** — `policy.yaml attention.enabled=false` ⇒ no production,
   no enqueue, liveness gated; canonical outcomes flow unchanged; `true`
   resumes. Contract tested end-to-end through `transitionOutcome`.
5. **Registry + item authorization** — `/ui/action` loads the item and
   requires the submitted `{key,args}` to match a STORED action ref (args
