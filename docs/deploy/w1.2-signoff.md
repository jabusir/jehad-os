# W1.2 sign-off — Mobile Dogfood Completion

Base `a5396bd` · final see git log · the interface-plumbing wave: from the
phone, with no Terminal and no Mac interaction, authenticate → delegate a
durable mission → leave → later receive and handle its Attention result.

**Product principle honored:** the user chooses the verb (TODAY | DELEGATE |
MISSIONS); natural language is only the content of structured fields. No
intent classifier, no routing model, no CognitiveEnvelope, no AI-generated
criteria, no model calls, no chat dependency.

## 1. Tailscale auth architecture

```
GET /ui (any /ui* GET)
  → valid Today session? yes → render
  no → Tailscale-User-Login (the ONLY auth header consulted)
     → exact allowlist (out-of-repo JSON config)
     → exact principal by NAME (type=user, credential present)
     → issue NORMAL Today session (same cookie/CSRF/scoping) → render
  else → fail closed (recovery link, never a credential prompt)
```

- API still bound to 127.0.0.1; Tailscale Serve is the only remote transport;
  **Funnel not enabled** (`tailscale serve status` = tailnet-only proxy).
- Mapping config: `~/.config/jehad/today-auth.json` (0600, OUTSIDE the repo —
  contains personal identity). Shape documented in ADR-0020; the exact mapped
  login is the tailnet owner login observed from live Serve traffic and
  `tailscale status` (is-owner + CapMap tailnet-display-name agree —
  unambiguous). REDACTED here by design.
- Loader: `apps/api/src/tailscale-auth.ts` — memoized per process,
  notifications-config lifecycle (restart to apply), fail-closed everywhere.
- **Local-host caveat:** a process already on the mini can reach localhost and
  forge headers; host compromise is outside the remote-client trust boundary.

## 2. Exact principal-mapping mechanism

`resolveTailscalePrincipal(db, headers, policy)`: enabled? →
`Tailscale-User-Login` trimmed → `policy.identities[login]` exact match →
`findPrincipalByName` → require `type === "user"` AND `credentialHash !== null`
(session keys derive from the credential hash) → return the principal →
`issueSession(principal.id, credentialHash, now)`. Every other case returns
null (fail closed).

## 3. Recovery-login behavior

`GET /ui/recovery` renders the existing credential-paste form;
`POST /ui/session` is byte-identical to W1 (preserved for compatibility).
Normal `/ui` never tells an allowlisted user to mint a credential; without a
valid session or allowlisted identity it renders a fail-closed page linking to
recovery. Bearer API auth unchanged.

## 4. Shared delegation seam (CLI + web)

`packages/workflow/src/delegate-shared.ts` → `createAndDispatchOutcome`:
policy enabled gate → goal/directive/criteria validation (≥1 criterion,
service-max bounded) → **idempotency first** (`outcome.delegate_requested`
event keyed `delegate:<principalId>:<submissionId>`; duplicate retry recovers
via the `delegate_created` marker and never re-creates/re-dispatches) →
**policy active-outcome cap** (same check/numbers as the CLI path) →
`createOutcome` (canonical row + criteria + budget/deadline defaults + audit)
→ dispatch via the WorkflowRuntime port (`outcome-executor`, exactly once).
Both `josctl delegate` (apps/cli/src/commands/ops.ts) and `POST /ui/delegate`
call it. The form's hidden `submissionId` (uuid) is rendered at GET time.

## 5. Delegate form contract

`GET/POST /ui/delegate` (session; POST + CSRF). Server-rendered, no JS:
goal (required, ≥4 chars), Done means ×4 (≥1 required), Constraints ×4
(optional), Deadline datetime-local (optional; must parse and be future),
hidden csrf + submissionId. Principal comes ONLY from the session (a forged
`principalId` field is ignored — tested). The Delegate button is the explicit
authority; no second confirmation (no policy requires one). Confirmation page
shows the REF + link to Missions.

## 6. Missions view contract

`GET /ui/missions` (session). Read-only projection: Needs-you (waiting_user,
blocked) / Running (accepted, queued, running, waiting_external, verifying) /
Recently finished (completed/failed/cancelled, ≤7 days, ≤20 rows). Row: title,
REF, status, updated age, deadline if present, [Open] → `/ui/outcome/:ref`
(principal-scoped; foreign refs 404). No analytics, no timeline, no worker
debug.

## 7. Navigation

Server-rendered nav shell in `page()`: Today | Delegate | Missions. No SPA, no
client framework, zero JS. Mobile CSS: 16px inputs (no iOS focus-zoom), ≥44px
touch targets, viewport meta, overflow-wrap — no horizontal overflow.

## 8. Security tests (all passing)

Tailscale auth (9): allowlisted login → correct principal session (cookie flags
Secure+HttpOnly+SameSite=Strict asserted); unlisted/missing/display-name-only/
empty-header logins denied; non-user and credential-less mapped principals
denied; disabled config authorizes nothing; mapping cannot cross principals
(second principal's items invisible); recovery credential path works; bearer
route still 401s without Authorization; CSRF enforced after auto-login.
Delegate (7): GET requires session; POST requires CSRF; principal from session
only; empty/short goal, zero criteria, malformed + past deadline denied; extra
form fields beyond the rendered rows ignored; valid submission → exactly ONE
outcome + canonical criteria rows + honored deadline + exactly ONE dispatch;
duplicate retry → "Already delegated", 1 outcome, 1 dispatch; policy cap still
applies (400 "policy cap"); CLI/web canonical event parity. Missions (5):
session required; grouping correct; 22-window finishers → exactly 20 rendered,
30-day-old excluded; hostile `<script>` escaped; foreign principal invisible +
foreign ref 404.

## 11. Terminal/Mac-interaction requirement

None. The entire loop — authenticate, delegate, confirm, re-authenticate via
deep link, act on the card — was executed against the live tailnet URL with
fresh, cookie-less sessions (exactly what a new phone browser session does).
The physical taps on the owner's iPhone are the OWNER DOGFOOD step; no
engineering remains between the phone and those taps.

## 12. Remaining friction / deviations

- The identity allowlist config is a manual JSON edit + process restart
  (deliberate: owner-controlled mapping, no admin surface in W1.2).
- Fixed 4+4 rows (no JS) — matching the directive's "simple is better" choice;
  the service still accepts up to the existing maximum via the shared seam.
- Idempotency is bounded to the delegate route (submissionId), per directive.
- Deviations: none from the directive. W2/Watches/chat/cognition/model calls
  untouched.
